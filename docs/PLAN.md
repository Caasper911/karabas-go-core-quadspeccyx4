# План QuadSpeccyX4

Цель: 16 Pentagon 128 на Karabas Go / Mini / Mini G, все на одном экране сеткой 4×4 (paper через пиксель, бордюр
в 1 пиксель) и выбранный на весь экран. Устройство в [ARCHITECTURE.md](ARCHITECTURE.md).

Порядок — от главного риска: сначала процессор на 8 машин по такту на каждую (если он не сходится по таймингу при
28 МГц, цель снижается до 8 машин на двух `tv80_quad`), потом шинная логика и память, потом экран и плата.

## Программы (запрос пользователя 2026-11-15)

- [x] `software/launcher/rndsna.asm`: `.rndsna <папка>` — случайный `*.SNA` папки. Два прохода по каталогу
      (F_OPENDIR / F_READDIR / F_REWINDDIR: счёт, затем N-й), индекс = xorshift16(FRAMES, R) mod N, запуск —
      `M_EXECCMD "snapload <папка>/<файл>"` из заглушки под SP в ОЗУ машины (SNAPLOAD грузится на место команды в
      2000h). Файл `RNDSNA`, 1180 байт
- [x] `rndtap.asm`: `.rndtap <папка>` — случайный `*.TAP` (общая часть с `.rndsna` — `rndsel.inc`): заглушка
      делает `M_EXECCMD "tapein <папка>/<файл>"`, кладёт `LOAD ""` в E_LINE и уходит из ESXDOS, как его выход по
      ошибке (SP из ERR_SP + 2, `#E3` из 3DF8h, `jp (hl)` в 1FFBh — зона выключения DivMMC), в MAIN-3 (12CFh) ПЗУ
      48 BASIC: LINE-RUN выполняет `LOAD ""`, возврат в MAIN-4 через (ERR_SP). Из 128 BASIC включает ПЗУ 1
      (BANKM бит 4, если бит 5 = 0) и сбрасывает FLAGS бит 4. Файл `RNDTAP`, 1250 байт
- [x] `rndtrd.asm`: `.rndtrd <папка>` — случайный `*.TRD` (запрос 2026-11-17; SCL пользователь переводит в TRD сам):
      заглушка делает `M_EXECCMD "vdisk 0 <папка>/<файл>"` (диск A эмулятора TR-DOS, BETADISK.SYS), кладёт в E_LINE
      `RANDOMIZE USR 15619: REM : RUN "boot"` (число со скрытой формой) и уходит в MAIN-3 ПЗУ 48 BASIC, как
      `.rndtap`. Файл `RNDTRD`, 1389 байт
- [x] `.rndtrd` не запускал `boot` (2026-11-17/19). Причины: (1) в образе были SYS-файлы ESXDOS с карты v6z80p, не
      0.8.9 — пользователь заменил их, `build.sh` теперь берёт SYS / BIN / TMP из дистрибутива `esxdos089.zip` (его
      ESXMMC.BIN = `src/roms/esxdos089.bin`); со старыми SYS ZEsarUX перезапускался по кругу после BETADISK.SYS;
      (2) выход из ESXDOS в обход его возврата (как в `.rndtap`: SP из ERR_SP, `jp (hl)` в 1FFBh) ломает эмуляцию
      TR-DOS: 15619 возвращает «0 OK, 0:1» или пишет «Disc Error». Теперь заглушка после `vdisk` заменяет программу
      строкой `10 RANDOMIZE USR 15619: REM : RUN`, ставит NEWPPC = 10, NSPPC = 0 и возвращается в ESXDOS, как любая
      dot-команда. Попытка создавать переменные TR-DOS самому (по старому TRDOS54T.KO) была ложным следом и убрана.
      Проверено в ZEsarUX 10.2 (Pentagon, DivMMC 128 КБ, наш ПЗУ ESXDOS, образ `demotrd.img`): с AUTOBOOT.BAS и
      набранной в 48 BASIC командой демо запускается; F_READDIR отдаёт короткие имена (`/DEMOTRD/0090.TRD`).
      Файл `RNDTRD`, 1314 байт
- [ ] Железо: `.rndtrd` на плате; диски без файла `boot` (TRDBOOT.BIN при AlwaysBoot=1); из 128 BASIC
- [ ] `.rndtap` выходит из ESXDOS тем же обходным путём — проверить в ZEsarUX, не ломает ли он эмуляцию ленты
- [x] Образ SD с демо (запрос 2026-11-17): `software/img/build.sh` → `demotrd.img`, FAT32 512 МБ (256 МБ мало: 522 TRD

## R после сброса (запрос пользователя 2026-11-15)

- [x] R после сброса у каждой машины свой, псевдослучайный (у Z80 — 0): LFSR 16 бит в движке на каждом такте,
      машина в сбросе берёт его в свой шинный слот (`c_seed`), CPU загружает R из него в слотах сброса (вход
      `rseed` tv80_core); R — значение последнего такта сброса, зависит от того, когда сброс кончился (загрузка ROM
      MCU, F12). `run_wall.sh`: эталон получает то же значение, сравнение R ловит подмену на 0
