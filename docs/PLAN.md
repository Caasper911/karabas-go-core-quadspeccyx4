# План SpeccyWall

Цель: 16 Pentagon 128 на Karabas Go / Mini / Mini G, все на одном экране сеткой 4×4 (paper через пиксель, бордюр
в 1 пиксель) и выбранный на весь экран. Устройство в [ARCHITECTURE.md](ARCHITECTURE.md).

Порядок — от главного риска: сначала процессор на 8 машин по такту на каждую (если он не сходится по таймингу при
28 МГц, цель снижается до 8 машин на двух `tv80_quad`), потом шинная логика и память, потом экран и плата.

## Milestone 1: процессор на 8 машин (`tv80_oct`)

- [x] Репозиторий, сабмодуль `modules/` (karabas-go-modules), tv80 из QuadSpeccy
- [x] Генератор `tools/mkctx.py` (N контекстов, второй порт чтения для выходов вместо слота «просмотра»),
      `tv80_oct.v`
- [x] Тест эквивалентности `src/sim/run_tv80o.sh`: восемь `tv80_core` против `tv80_oct`, все выходы каждый такт и
      внутреннее состояние раз в T-состояние; 0 ошибок на 2 млн тактов с SEED 1, 2, 3
- [x] Найдено тестом: запись регистрового файла в такте синхронного сброса (исправлено в генераторе; в `tv80_quad`
      QuadSpeccy та же разница)
- [x] Тайминг отдельно (`src/test/run_timing.sh`): 22,7–24,4 нс при бюджете 35,7, 564–582 слайса (15 %);
      `tv80_quad` тем же стендом 21,2 нс, 512 слайсов
- [x] Мутационная проверка теста: `IR`, `A`, `IntCycle` через порт чужого CPU, `SP` из контекста 0 — пойманы
      (`F` второго mcode на его выходы не влияет)

## Открытые вопросы

- Распаяна ли SRAM на Mini и Mini G так же, как на Go (выводы `MA` / `MD` есть во всех трёх ucf)?
- SRAM за 2 такта `clk_sys` (12 обращений на T вместо 8) — по расчёту TS-Conf не проходит (12 нс выход + 10 нс tAA
  + 12 нс вход), только с проверкой на плате.
- Прореживание или OR пар пикселей в ячейке: смотреть на мониторе.
- Тайминг `tv80_oct` в полном ядре: отдельно 22,7–24,4 нс, `tv80_quad` в ядре QuadSpeccy вырос с 21,2 до 31,4 нс.
