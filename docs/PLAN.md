# План SpeccyWall

Цель: 16 Pentagon 128 на Karabas Go / Mini / Mini G, все на одном экране сеткой 4×4 (paper через пиксель, бордюр
в 1 пиксель) и выбранный на весь экран. Устройство в [ARCHITECTURE.md](ARCHITECTURE.md).

Порядок — от главного риска: сначала процессор на 8 машин по такту на каждую (если он не сходится по таймингу при
28 МГц, цель снижается до 8 машин на двух `tv80_quad`), потом шинная логика и память, потом экран и плата.

## Milestone 1: процессор на 8 машин (`tv80_oct`)

- [x] Репозиторий, сабмодуль `modules/` (karabas-go-modules), tv80 из QuadSpeccy
- [x] Генератор `tools/mkctx.py` (N контекстов, второй порт чтения для выходов вместо слота «просмотра»),
      `tv80_oct.v`
- [x] Тест эквивалентности `src/sim/run_tv80o.sh`: восемь `tv80_core` против `tv80_oct`, все выходы каждый такт и
      внутреннее состояние раз в T-состояние; 0 ошибок на 2 млн тактов с SEED 1, 2, 3
- [x] Найдено тестом: запись регистрового файла в такте синхронного сброса (исправлено в генераторе; в `tv80_quad`
      QuadSpeccy та же разница)
- [x] Тайминг отдельно (`src/test/run_timing.sh`): 22,7–24,4 нс при бюджете 35,7, 564–582 слайса (15 %);
      `tv80_quad` тем же стендом 21,2 нс, 512 слайсов
- [x] Мутационная проверка теста: `IR`, `A`, `IntCycle` через порт чужого CPU, `SP` из контекста 0 — пойманы
      (`F` второго mcode на его выходы не влияет)
- [ ] Покрытие INT: в трёх сидах CPU 6 и 7 не взяли ни одного прерывания (EI / IM в случайном коде редки),
      сделать стимул, который их гарантирует

## Milestone 2: машина как движок на 8 контекстов + память

На железе проверить пока нельзя: всё в симуляции и пробных сборках.

- [x] Движок `zx_oct`: tv80o_core + шинная логика Pentagon 128 на контекстах (`#FE`, `#7FFD`, страницы, копия AY,
      Kempston, INT в слоте 0 для всех), шинный слот машины *k* — слот *k* + 1
- [x] Память без очереди и WAIT: один запрос в такт (только машина слот − 1), данные через 3 такта при бюджете 15
- [x] Контроллер SRAM `sram_ctrl`: обращение за такт `clk_bus` (адрес и `/RD` в IOB на `clk_bus`, чтение фронтом
      `clk_bus`, `/WR` и данные записи на `clk_sys` в средней трети), порт видео на свободных тактах
- [x] ROM 128 / 48 в блочной памяти (16 RAMB16), общий, порт загрузчика
- [x] Общий растр `zx_timing` (из QuadSpeccy); задержка растра машины на её слот — в milestone 3 (видео)
- [x] Модель SRAM `sram_model.v` с проверкой таймингов (tAA, tWP, tAS / tAW, tDW / tDH, столкновение на шине)
- [x] Тест `run_wall.sh`: 8 машин против 8 эталонных (`tv80_core` + поведенческая шина) — все выходы CPU каждое
      T-состояние, байт, который CPU берёт, память, порты, AY; случайный код: 0 ошибок на 2 млн тактов
- [x] Найдено прогонами ROM в самом тестбенче: байт эталона через функцию в непрерывном присваивании не следил за
      памятью (только за адресом); DI в цикле без чтения у эталона был байтом памяти по адресу, а у движка (и
      `pentagon` QuadSpeccy) — последним прочитанным; tv80 берёт DI и после такого цикла (JR), прогон ROM расходился
      на кадре 48. Эталон теперь по правилу движка; добавлены сравнения байта, который берёт CPU, и внутреннего
      состояния CPU каждое T-состояние
- [x] ROM 128: 64 кадра (36,7 млн тактов), все 8 машин до меню 128, 0 ошибок, снимок экранов (`ROM=1`)
- [x] То же с одновременным стартом (`SAME=1`): все 8 в ногу, 0 ошибок
- [x] Пробная сборка `run_timing.sh wall8`: 1679 LUT, 563 слайса (14 %), 16 RAMB16, `clk_bus` 21,3 нс из 35,7,
      тайминги SRAM как в TS-Conf выполнены

      загрузчик ROM прямо в блочную память), `zx_kbd` на 8 машин (Win+1..8, стрелки по сетке 4 × 2), сбросы, NMI
- [x] Экран выбранной машины: `zx_scr` (выборка парами знакомест через порт видео `sram_ctrl`), `vga_out` на `pclk`:

- [x] Звук выбранной: beeper, MIC, лента, один AY (`ay_psg`), загрузка регистров AY при смене машины
- [x] Тест видео `run_video.sh`: каждая точка обоих режимов против памяти, при занятом CPU порте SRAM — 0 ошибок
- [x] Сборка `make go`: все constraints выполнены; 3147 LUT, 1047 слайсов (27 %), 18 RAMB16 + 5 RAMB8; `clk_bus` 32,7 нс
      из 35,7 (путь CPU), `pclk` 13,51 из 13,59 (смешение OSD в `kg_l2_osd_overlay` от его настроек, которые меняются

- [x] Железо: на плате машины не работали — ошибка XST в контекстах `zx_oct` (массив, записанный в обеих ветках

      симуляцией netlist (`run_ps.sh`); исправлено одной записью каждого контекста за такт
- [x] Железо: машины работают (2026-11-14); монитор Dell принял 1280×800 при 48,88 Гц, серая рамка видна целиком
- [x] Железо: все 8 машин, переключение, клавиатура, звук, BASIC в нескольких машинах сразу, полосы, 720×576 —
      всё работает (2026-11-14)

## Открытые вопросы

- [x] SRAM на Mini и Mini G есть: её использует karabas-go-core-tsconf на всех трёх платах.
- [x] Запись SRAM на плате: `/WR` 11,9 нс в средней трети такта — самотест 2M слов на Go без ошибок.

  + 12 нс вход), только с проверкой на плате.
