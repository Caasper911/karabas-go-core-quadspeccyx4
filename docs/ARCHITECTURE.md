# Архитектура SpeccyWall

Шестнадцать Pentagon 128 на XC6SLX25 (Karabas Go, Mini, Mini G). Разделы «Процессор», «Машины» и «SRAM» описывают
сделанное, «Целевая схема» — то, по чему идёт работа ([PLAN.md](PLAN.md)). Инфраструктура платы (MCU link v2, PLL, OSD, сборка
Makefile, `core.json`) та же, что в QuadSpeccy и karabas-go-core-tsconf; первое ядро для Go — раздел «Первое ядро».

## Почему не 16 отдельных машин

QuadSpeccy (4 машины) на Go занимает 7202 LUT, 2660 слайсов (70 %). Машина там — модуль `pentagon` (~360 LUT) с
DivMMC и эмулятором SD (`kg_sd_emu`, ~290 LUT); четыре CPU — один `tv80_quad` (1499 LUT, ~520 слайсов). Даже без
DivMMC, SD и мыши машина остаётся около 90–130 слайсов, 16 таких и четыре `tv80_quad` — 104–114 % кристалла.
Поэтому в SpeccyWall и процессор, и шинная логика машины — одна логика на восемь машин, состояние машины — ячейка в
распределённой памяти (контекст), как регистры CPU в `tv80_quad`.

## Клоки (как в QuadSpeccy)

Один PLL от `CLK_50MHZ`, VCO 925 МГц: `clk_sys` 84,09 МГц (/11, SDRAM и SRAM), `clk_bus` 28,03 МГц (/33, всё
остальное). Восемь тактов `clk_bus` — одно T-состояние Z80 (3,504 МГц).

## Процессор: один tv80 на восемь машин (`tv80_oct`)

- `tools/mkctx.py` делает из `tv80_core.v` ядро на N контекстов (`tv80o_core.v` для N = 8, в `src/rtl/tv80/`): логика
  (mcode, ALU, всё комбинационное) одна, каждый из 48 регистров состояния — память на 8 записей `X_m[th]`, регистровый
  файл `tv80o_reg` — 64 записи. Блоки `always` пишут `X_m[th] <= X_n` в конце, асинхронный сброс становится
  синхронным. Это обобщение `tools/mkquad.py` QuadSpeccy.
- **Один такт на CPU.** Слот *k* (из 8) — `cen` CPU *k*: его состояние читается и пишется, входы (данные, WAIT,
  INT, NMI, сброс) берутся в этом такте. В `tv80_quad` CPU нужно было два такта: `cen` и «просмотр», в котором та же
  логика показывала выходы нового состояния. Здесь выходы идут через **второй порт чтения** состояния (`pth` =
  слот − 1): регистры, из которых складываются выходы (`A`, `dout`, `m1_n`, `mcycle`, `tstate`, `Halt_FF`,
  `IntCycle`), и вход второго `tv80_mcode` (`IR`, `ISet`, `mcycle`, `F`, `NMICycle`, `IntCycle`), от которого нужны
  только `IORQ`, `NoRead`, `Write` (XST оставляет лишь их конус). Выходы CPU *k* живые в слоте *k* + 1 и держатся
  в регистре `kept` до того же слота следующего T-состояния: машина видит обычный tv80, чей `cen` в слоте *k*.
- **Сброс.** Регистровый файл не пишется, пока у CPU активен `reset_n`. Эталонный `tv80_core` сбрасывается сразу
  (асинхронно) и в такте сброса ничего не пишет, а здесь в такте синхронного сброса логика ещё видит старое
  состояние; регистровый файл сбросом не очищается, и такая запись меняла бы регистр (тест нашёл это на CPU 4
  через 1,5 млн тактов). В `tv80_quad` QuadSpeccy эта разница есть, её тест там не поймал.
- **Проверка.** `src/sim/run_tv80o.sh` (`tb_tv80o.v`): восемь `tv80_core` и `tv80_oct` на одном клоке, у каждого CPU
  свои 64 КБ случайного кода (каждый 8-й байт ED, HALT заменён на EI), случайные WAIT / INT / NMI / пропуски `cen`
  / сбросы. Каждый такт сравниваются все выходы каждого CPU, раз в T-состояние — его внутреннее состояние (ACC, F,
  PC, SP, I, регистровый файл): ошибка внутри видна раньше, чем дойдёт до выводов. `SEED` задаёт случайный поток.
  Мутации (`NOGEN=1`, чтение `IR`, `A`, `IntCycle` через порт не того CPU, `SP` из контекста 0) тест ловит за
  200–1200 тактов; `F` второго mcode не ловится и не может: `IORQ` / `NoRead` / `Write` от флагов не зависят (XST
  этот вход отрезает).
- **Тайминг отдельно от ядра** (`src/test/run_timing.sh`, `cpu8_top.v`: PLL ядра, входы с LFSR через регистры,
  выходы свёрнуты XOR на вывод): `tv80_oct` — минимальный период 22,7–24,4 нс (два прогона) при бюджете 35,7
  (28 МГц), около 1890 LUT, 511 регистров, 564–582 слайса (15 %). Тем же стендом `tv80_quad` — 21,2 нс, 1605 LUT, 512 слайсов (13 %); в полном ядре
  QuadSpeccy при 70 % слайсов у него 31,4 нс. Значит, восемь CPU стоят на 10 % слайсов больше четырёх, а запас по
  таймингу в ядре надо ждать того же порядка, что у QuadSpeccy (около 4 нс), — проверится на полной сборке.

## Машины: движок `zx_oct` (8 машин)

`src/rtl/zx/zx_oct.v`: восемь Pentagon 128 на одном `tv80o_core` и одной шинной логике; состояние каждой машины —
контексты в распределённой памяти (индекс — номер машины). Слоты те же, что у `tv80_oct` (слот 0 — такт `ce_cpu`
растра):

- **слот *k*** — `cen` CPU *k*; его входы берутся из контекстов машины *k*: данные (`c_src` ? `c_pdat` : `c_mdat`),
  DI (`c_di`, данные T2 по образцу T80se), INT, NMI, сброс. В цикле без чтения (внутреннем, записи) CPU получает
  последний прочитанный машиной байт памяти (`c_mdat`), как `pentagon` QuadSpeccy (его регистр данных SDRAM держит
  последнее чтение): T80se берёт DI в каждом T2, а tv80 пользуется им и после такого цикла (смещение JR — в его
  внутреннем M3);
- **слот *k* + 1** — шинная логика машины *k*: новые выходы CPU *k* со второго порта (`p_*`), декодирование
  (как `pentagon.v` QuadSpeccy по `cen_d`), запрос в память, запись портов, данные порта для CPU.

**Память без очереди и без WAIT.** Запрос в такте даёт только одна машина (слот − 1), а SRAM делает одно обращение
за такт: запросы восьми машин никогда не встречаются. Чтение выдаётся в начале T1 (шинный слот), данные приходят
через 3 такта (`c_mdat`), CPU берёт их в конце T2 — через 15 тактов после запроса. Запись — в начале T2. ROM (128 и
48 BASIC, 32 КБ) — общая блочная память (16 RAMB16), её данные задержаны до той же задержки 3, так что возврат один в
такт. RAM машины *m* — 128 КБ SRAM по байтовому адресу {`BASE`, *m*, страница, смещение} (`BASE` — мегабайт движка).

**Порты** как Pentagon 128: `#FE` (A0 = 0; чтение — клавиатура и лента выбранной машины `sel`), `#7FFD` (A15 = 0,
A1 = 0, с блокировкой), AY `#FFFD` / `#BFFD` (A15 = 1, A1 = 0): копия 16 регистров каждой машины (`ay_ram`, 128 × 8),
записи выбранной идут наружу (`ay_*`) к одному AY; Kempston `#1F` выбранной. Данные чтения порта берутся в каждом
шинном слоте цикла ввода (последний перед тактом CPU и считается), FF в M1 подтверждения прерывания. INT — значение в
слоте 0 для всех CPU (каждая машина в том же отношении к своему INT, как `raster_delay` QuadSpeccy). Сброс должен
длиться не меньше 16 T: регистры AY очищаются по одному за T-состояние (сброс ядра и OSD — миллисекунды).

**Видео** читает бордюр и экран машины `v_m` (`v_border`, `v_scr7`; асинхронные порты контекстов).

**Контексты пишутся одним присваиванием за такт.** Следующие значения контекстов машины *b* считаются комбинационно
(`n_*`), в шинном слоте каждый массив пишется один раз. Причина — ошибка XST 14.7, найденная на плате: массив,
который писался в обеих ветках `if (reset[b]) … else …` (`c_t2[b] <= 0` / `c_t2[b] <= t2`), стал RAM16X1D с
разрешением записи от мультиплексора сброса и данными `t2 & ~` того же сигнала — писались только нули. RTL-тесты
этого не видят; ни одна машина на плате не работала (CPU получал DI = FF: `c_di` пишется по `c_t2`).
`src/sim/run_ps.sh` (`tb_ps.v`): `zx_oct` после XST (netgen) против RTL на загрузке ROM 128, все выходы каждый такт —
запускать после изменений логики контекстов.

**Проверка** — `src/sim/run_wall.sh` (`tb_wall.v`): движок на `sram_ctrl` и модели SRAM против восьми эталонных
машин: `tv80_core` с поведенческой шиной (своя память без задержки, порты и `#7FFD` написаны в тестбенче заново,
`cen` в слоте *k*). Каждое T-состояние все выходы CPU *k* движка (слот *k* + 1) и его внутреннее состояние (ACC, F,
PC, SP, I, IFF, IR, INT_s, DI, регистровый файл) сравниваются с эталонным CPU *k*, а в каждом такте, где CPU берёт
байт, — сам байт; в
конце — 128 КБ каждой машины в модели SRAM против памяти эталона, бордюр, beeper, MIC, `#7FFD`, регистры AY. Ещё:
флаг `late` ни разу, модель SRAM без нарушений, читатель видео (`v_req`) над областью машин читает то, что должен.
Режимы: случайный код (как `tb_tv80o`: случайные ROM и RAM, INT, NMI, сбросы, клавиши, выбранная машина) и ROM 128
(`ROM=1`: загрузка ROM через порт загрузчика, машины выходят из сброса по очереди через 1000 T, снимок экранов
`work_w/screens.png`, `tools/render_wall.py`).

**Ресурсы** (`src/test/run_timing.sh wall8`: движок + `sram_ctrl` на выводах SRAM Go, PLL ядра): 1679 LUT (282 —
LUTRAM), 294 регистра, 563 слайса (14 %), 16 RAMB16 (ROM) + 1 RAMB8; `clk_bus` 21,3 нс из 35,7, `clk_sys` 7,5 из
11,9; `TS_SRAM_OUT` / `TS_SRAM_IN` (12 нс, как в TS-Conf) выполнены, запас 7,8 нс. Меньше, чем `tv80_oct` отдельно:
выходы CPU не держатся в регистрах `kept` на каждую машину, шинная логика берёт их со второго порта в своём слоте.

## SRAM: `sram_ctrl`

`src/rtl/mem/sram_ctrl.v`: SRAM платы 2M × 16 (10 нс, `/RD` и `/WR` на байт: `MRD_N`, `MWR_N`; CS на земле; есть на
Go, Mini и Mini G — её использует TS-Conf), одно обращение за такт `clk_bus`:

- запрос в такте *n* (CPU: `c_req` на такт; видео: `v_req` до `v_ack`, в такте без запроса CPU);
- *n* + 1: `MA` и `MRD_N` из регистров на `clk_bus` (IOB) весь такт. Чтение: слово берётся фронтом `clk_bus` в конце
  такта (IOB): 35,7 нс = 12 нс выход + 10 нс tAA + 12 нс вход + плата, как в TS-Conf (там три такта `clk_sys`).
  Запись: `/WR` байта низкий от первого до второго фронта `clk_sys` такта (11,9 нс), данные — от первого до третьего:
  адрес и данные по такту `clk_sys` до и после `/WR`; при записи `/RD` высокий весь такт, поэтому SRAM отпускает шину
  в начале такта, а данные выходят на такт `clk_sys` позже (без столкновения после чтения);
- *n* + 2: слово `q` (CPU или видео).

Фаза `clk_sys` в такте `clk_bus`: `bt` переключается на `clk_bus`, `bts` берёт его на `clk_sys`; `bt != bts` в первом
такте `clk_sys` (оба клока из одного PLL, каждый фронт `clk_bus` — фронт `clk_sys`). Модель `src/sim/sram_model.v`
проверяет tAA (X до валидности), ширину `/WR`, установку и удержание адреса и данных, столкновение на шине; на плате
это ещё надо проверить (задержки выводов в симуляции нулевые).

## Первое ядро для Go (`speccywall.v`)

Восемь машин и выбранная на весь экран — чтобы проверить на плате движок, SRAM и режим 1280×800 до сетки 4×4.
`src/rtl/speccywall.v` (всё, кроме платы) и `src/rtl/karabas_go_top.v`; сборка `cd src && make go` (Makefile, prj,
xst, ut — как в QuadSpeccy), `core.json` (link v2).

- **Клоки**: PLL 1 как в QuadSpeccy (`clk_sys`, `clk_bus`, `clk_8`); PLL 2 от `clk_bus` (BUFG): ×21 / 8 → `pclk`
  73,6 МГц — растр VGA, OSD, `V_CLK`. `V_CLK` = инвертированный `pclk` через ODDR2: ЦАП берёт точку фронтом в
  середине точки. Переходы `clk_bus` → `pclk` (буфер строк в блочной памяти, метка кадра через три регистра,
  статические настройки) в ucf как TIG.
- **MCU**: `kg_mcu2` без монтировщика образов (`ENABLE_IMG` 0), FT812 — только для MCU, как в QuadSpeccy. Загрузчик ROM
  пишет 32 КБ (`core.json`: 128 по адресу 0, 48 по 16384) прямо в блочную память `zx_oct` по байту в такт
  (`LD_READY` всегда 1), машины в сбросе. Сбросы: старт, загрузка, Reset All (OSD, Menu+F12, кнопка 1) — все,
  Reset (F12, кнопка 0) — выбранная; сброс держится не меньше 255 тактов (32 T: AY очищается по регистру за T).
- **Клавиатура** (`src/rtl/hid/zx_kbd.v` из QuadSpeccy): Win+1..8 — машина, Win+стрелки — соседняя в сетке 4 столбца
  × `ROWS` рядов (`sel` 4 бита, на 16 машин). Клавиши и Kempston идут в `zx_oct`, тот отдаёт их выбранной.
- **Экран** выбранной машины: `src/rtl/video/zx_scr.v` — выборка как в `pentagon.v` QuadSpeccy, но слово SRAM — два
  знакоместа: пара знакомест (слово пикселей, затем слово атрибутов) в один из двух буферов пары, через порт видео
  `sram_ctrl` (ждёт такта без запроса CPU: подряд не больше 8, на пару уходит меньше 24 тактов из 64). Растр —
  `zx_timing` (машины 0): машина *m* идёт на *m* тактов позже, картинка на столько же раньше (точный растр машины —
  со стеной). `src/rtl/video/vga_out.v` на `pclk`: кольцо из 4 буферов строк (`vc[1:0]`, запись на `clk_bus`), строка
  VGA `py` показывает строку Спектрума `py / 3` (`py / 2`), пока Спектрум пишет `py / 3 + 2`; счётчики `pclk`
  ставятся в строку 0, когда Спектрум в строке 2, точке 0 (и снова — только если разошлись больше чем на 7 тактов,
  чтобы синхронизатор не дёргал картинку). Два растра (OSD «Video», Menu+V):
  - **1280×800** (1568 × 960, 48,88 Гц): полный экран ×3 — 352 × 266 точек Спектрума = 1056 × 798 с x = 112, y = 1;
    вокруг серая рамка в 1 точку по краям 1280 × 800 (видно, всё ли показывает монитор) и чёрные поля, по OSD «Side
    stripes» — вертикальные полосы в 1 точку (фаза монитора); hsync 128 (64 / 96) отрицательный, vsync 6 строк (3 /
    151) положительный, как CVT 1280×800;
  - **720×576** (по умолчанию: растр QuadSpeccy, проверенный на мониторах): 2352 × 640 `pclk` = 896 × 640 тактов
    28 МГц, точка Спектрума 5,25 `pclk` (накопитель 4 / 21), видимо 368 × 288 точек = 1932 `pclk` × 576 строк;
    синхро отрицательные.
  OSD (`kg_l2_osd_overlay`) на `pclk`, центруется по `de`.
- **Звук**: beeper, MIC, вход ленты выбранной машины и один AY (`ay_psg` QuadSpeccy) с записями выбранной; при смене
  машины 16 регистров AY загружаются из копии в `zx_oct` (`ay_ra` / `ay_rd`), записи движка идут вперёд. ABC / ACB
  по OSD. Выход — PCM5102, `BEEPER`, `TAPE_OUT` (MIC выбранной).
- **Стена** (milestone 4, 1280×800; после старта, Win+` — полный экран выбранной и обратно; 720×576 — всегда
  полный экран). Сетка 4 × 4 ячеек 320 × 200 — весь экран 1280 × 800 (было 258 × 194 с рамкой в 1 точку и чёрными
  полями; пользователь попросил занять всё место): paper машины 4 *cr* + *c* в 1:1 в середине ячейки (x 32..287,
  строки 4..195), вокруг бордюр её цветом (32 точки по бокам, 4 строки сверху и снизу); ряды ячеек с `ROWS` (2:
  восемь машин) — серые; внешняя точка ячейки выбранной мигает белым (`frame[4]`).
  `src/rtl/video/wall_fetch.v` (`clk_bus`): строки VGA отсчитываются от той же метки кадра, что в `vga_out` (Спектрум
  в строке 2, точке 0 = `py` 0), по 597, 597, 598 тактов (1568 `pclk` = 597⅓); через 8 тактов после начала строки
  *R* читается строка *R* + 1: для каждой из 4 машин ряда `v_m` = машина (порт контекстов `zx_oct`, в стене его
  держит `wall_fetch`), через 2 такта берутся её бордюр и экранная страница, для строки paper — 16 слов пикселей и 16
  атрибутов (пары знакомест) конвейером через порт видео: `v_req` держится, по слову в каждом такте с `v_ack`, слово
  через 2 такта. Буфер ряда в `vga_out`: RAMB8 128 × 32 (запись `clk_bus`, чтение `pclk`), запись {чётность строки,
  столбец, пара} = {слово атрибутов, слово пикселей}; бордюры — 2 × 4 × 3 бита в регистрах. 128 чтений за строку из
  597 тактов: CPU оставляют не меньше 2 тактов из 3. Картинка — память в момент чтения: мультиколор в стене неточен
  (полный экран точен). Проверка — `run_video.sh` с `WALL=1`: каждая точка сетки против памяти восьми машин (у каждой
  своя страница и цвет бордюра), порт SRAM занят CPU по максимуму.
- **Самотест SRAM** (`src/rtl/mem/sram_test.v`): после старта ядра и по Reset All пишет все 2M слов узором от
  адреса (`a[15:0] ^ {a[20:16] ×3, 0}`: каждый бит адреса меняет какой-то бит данных) побайтно, путём записи CPU, и
  читает обратно; машины в сбросе (~0,2 с). Результат — в диагностике.
- **Диагностика** (OSD «Diagnostics», по умолчанию выкл.): шесть строк по 16 квадратиков в бордюре (`zx_scr`,
  зелёный 1): PLL, загрузчик, ROM, сбросы, обращения к SRAM, бордюр; итог самотеста, неверные биты данных, первый
  неверный адрес; PC выбранной машины, её `#7FFD`, бордюр и события (`zx_oct` `dbg_*`). Расшифровка в `speccywall.v`.
- **Симуляция всего ядра**: `src/sim/run_core.sh` (`tb_core.v`): `speccywall` с PLL на модели SRAM, ROM положен в
  `zx_oct` напрямую, `busy` MCU снят; печатает диагностику.
- **Проверка видео**: `src/sim/run_video.sh` (`tb_video.v`): `zx_timing`, `zx_scr`, `sram_ctrl` с моделью SRAM
  (случайные экранные страницы), `vga_out` на `pclk` = 21/8 `clk_bus` (точно, от общего шага 0,849 нс); порт CPU занят
  так, как его могут занять восемь машин (8 тактов подряд каждые 3 T; `BUSY=0` — случайно каждый второй). Каждая
  видимая точка VGA сравнивается с картинкой, посчитанной по памяти; длина строки, число строк, период кадра
  (1 505 280 `pclk`), полярность синхро. 0 ошибок в обоих режимах (по 2 кадра: 2,05 и 2,23 млн точек, страницы 5 и 7).
- **Сборка** (`make go`): 3147 LUT, 1047 слайсов (27 %), 18 RAMB16 + 5 RAMB8, все constraints выполнены: `clk_bus`
  32,7 нс из 35,7 (CPU: `slot` → регистровый файл, 13 уровней; QuadSpeccy в ядре 31,4), `clk_sys` 7,6 из 11,9, `pclk`
  13,51 из 13,59 — худший путь в смешении OSD (`kg_l2_osd_overlay`: от `alpha` / `bg`, которые оверлей берёт в начале
  кадра, дальше они стоят), SRAM 4,2 / 3,6 нс из 12.

## Целевая схема (16 машин)

### Память

- Два движка по 8 машин, оба в SRAM (2 МБ из 4; `BASE` 0 и 1). Каждый движок даёт не больше одного запроса в такт,
  вместе до двух при одном обращении SRAM за такт: нужна очередь. Машина обращается не чаще раза в 3 T (24 такта),
  поэтому даже если все 16 идут в ногу (после Reset All — один код), запросы движка разнесены по 8 слотам: очередь
  до 8, ожидание до 8 тактов + 3 задержки при бюджете 15. Видео ждёт свободных тактов (у него буфер строки).
  Средняя загрузка: 16 машин × 1/3 + видео ≈ 6,5 из 8 обращений на T-состояние в худшем случае. SDRAM не нужна.
- ROM общий, по блочной памяти на движок (16 RAMB16 каждый, 32 из 52) или одна на два движка через два порта.

### Видео: 1280×800, кадр Pentagon (решено 2026-11-14)

Выход 1280×800 вместо 720×576 QuadSpeccy: сетка 4×4 без прореживания (1:1) с бордюром, полный экран целым масштабом.

- **Растр** (основной): всего 1568 × 960, видимо 1280 × 800, пиксельный клок P = 21/8 × `clk_bus` = 73,6 МГц
  (второй PLL от `clk_bus`: M = 21, VCO 588,6 МГц, выход /8). 1568 × 960 = 2,625 × 573 440 — ровно кадр Pentagon,
  48,88 Гц; три строки VGA на строку Спектрума (960 = 3 × 320), поэтому VGA привязан к растру машин, как удвоитель
  строк QuadSpeccy. Гашение строки 288 точек, кадра 160 строк.
- **Сетка 4×4**: ячейка 320 × 200 — paper 256 × 192 в 1:1 и бордюр вокруг (32 точки по бокам, 4 строки сверху и
  снизу); 4 × 4 = ровно 1280 × 800. Строка VGA показывает одну строку Спектрума у 4 машин ряда (каждая строка Спектрума — одна строка VGA,
  не три): перед строкой компоновщик читает 4 × 32 слова (пиксели и атрибуты словами по 16 бит, порт видео
  `sram_ctrl`) в буфер ряда (RAMB8, два клока: запись на `clk_bus`, чтение на P), ~128 обращений за строку VGA
  (~600 тактов `clk_bus`). Картинка — экранная память в момент чтения (мультиколор в сетке неточен, как в quad-режиме
  QuadSpeccy); бордюр ячейки — цвет бордюра машины по строкам.
- **Полный экран** выбранной машины: масштаб 3 (три строки VGA на строку, три точки на пиксель): 352 × 266
  Спектрума = 1056 × 798 (paper 256 × 192, по 48 точек бордюра по бокам, по 37 строк сверху и снизу). Строка берётся
  из удвоителя по растру машины (как QuadSpeccy): эффекты бордюра и мультиколор точные.
- **Запасные режимы** (компоновщик и растр с параметрами): 1280×800 при 60 Гц (CVT-RB, 71 МГц) без привязки к кадру,
  если монитор не примет 48,88 Гц — тогда и полный экран читается построчно из памяти, без точных эффектов; 1024×768 с
  привязкой (1344 × 960, P = 9/4 × `clk_bus` = 63,1 МГц, сетка без бордюра), если на Mini не сойдётся HDMI.
- **HDMI (Mini)**: 5 × P = 368 МГц — у предела `DCM_CLKGEN` (375 МГц для -2), проверить сборкой; на Go (VGA) это не
  нужно. Телевизор по HDMI режим 48,88 Гц, скорее всего, не примет (не CEA), монитор — возможно.
- OSD (`kg_l2_osd_overlay`, масштаб 2) центруется по `de`, как в QuadSpeccy.

### Упрощения против QuadSpeccy

Нет DivMMC / Z-Controller / SD-карт, мыши, TurboSound (один AY выбранной машины), 1024 КБ Profi. OSD — общие
настройки и выбранная машина, а не страница на каждую. Дисковод (только Go) — один, у выбранной машины.
